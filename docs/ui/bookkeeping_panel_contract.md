| 项 | 值 |
|---|---|
| 行高 | **36 dp** |
| chip 宽度 | **按内容自适应** |
| chip 间距 | **8 dp**（水平） |
| chip 圆角 | **10 dp** |

| chip 内边距 | 左 **10** / 右 **12** / 上下 **6** |
| chip 内容 | 可选 16dp 图标 + 6dp 间距 + 文字 **13 sp** |
| 行内对齐 | 左对齐，**允许横向滚动** |

### chip 内容映射

| 位置 | 第 1 行 | 第 2 行 |
|---|---|---|
| 1 | **类型**：「支出 ▾」/「收入 ▾」/「转账 ▾」 | **标签**：已选标签，或「标签」 |
| 2 | **时间**：`HH:mm`（带时钟图标） | **成员**：已选成员，或「成员」 |
| 3 | **币种**：ISO（带币种标识） | **分类**：分类名（带分类图标）；转账时隐藏 |
| 4 | **附加**：未实现时**留空不渲染** | **账户**：账户名（带账户图标） |

### 类型切换（硬性要求）

1. 类型 chip **必须始终可见**
2. 不可删除、不可移到首页
3. 三个值：支出 / 收入 / 转账；当前值用主色 + 加粗
4. 切换联动：分类按 kind 过滤；不匹配则清空；转账隐藏分类
5. 结构测试必须断言类型 chip 存在

## 对执行者的约束

1. 本契约的数值是**实测值**，不是建议值。不要"优化"它们。
2. 若你认为某个值不合理，**不要改**——在报告中列出「位置 / 现值 / 建议值 / 理由」，由用户决定。
3. 任何**新增**的 UI 元素（图标、分隔线、标题、按钮）都必须先问：契约里有吗？没有 → 不加。
4. 间距/字号/圆角**只能**用契约里的值或 `CentliSpacing` / `textTheme` 里的既有 token，不得出现新的魔法数字。
5. 改完必须跑 golden + 结构测试，两者都过才算完成。

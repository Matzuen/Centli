## 类型切换（面板顶部，硬性要求）

类型不在 chip 行，而在面板顶部独立分段：**支出 | 收入 | 转账**。

1. 三个值必须始终可见，不可删除
2. 当前值用主色 + 加粗
3. 切换联动：分类按 kind 过滤；不匹配则清空
4. 转账时 chip 行显示「转出 / 转入」双账户，且**不渲染「附加」**（转账不能挂附加子交易）
5. 结构测试必须断言类型分段存在

### chip 内容映射（从左到右）

| 顺序 | Chip | 说明 |
|---|---|---|
| 1 | **时间** | `HH:mm`（时钟图标） |
| 2 | **分类** | 分类名（分类图标）；转账时仍可选转账分类 |
| 3 | **账户** | 非转账：`资产账户`；转账：`转出 · 名` + `转入 · 名` 两枚 |
| 4 | **标签** | 已选标签，或「标签」 |
| 5 | **附加** | 仅新建非转账时渲染；有草稿时显示「附加 · N」 |

**已移除（产品约定）**：成员 chip；商户独立 chip（商户并入备注）；币种独立 chip（币种跟金额同行显示）。

## 对执行者的约束

1. 本契约的数值是**实测值**，不是建议值。不要"优化"它们。
2. 若你认为某个值不合理，**不要改**——在报告中列出「位置 / 现值 / 建议值 / 理由」，由用户决定。
3. 任何**新增**的 UI 元素（图标、分隔线、标题、按钮）都必须先问：契约里有吗？没有 → 不加。
4. 间距/字号/圆角**只能**用契约里的值或 `CentliSpacing` / `textTheme` 里的既有 token，不得出现新的魔法数字。
5. 改完必须跑 golden + 结构测试，两者都过才算完成。

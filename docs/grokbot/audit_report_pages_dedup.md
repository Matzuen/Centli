## 1. 🔴 真重复

### D1 · 详情页「商户」与「备注」渲染同一个字段

`lib/features/ledger/ledger_detail_page.dart`

```dart
// :208-215  标题「商户」
ListTile(
  title: const Text('商户'),
  trailing: Text((txn.note == null || txn.note!.isEmpty) ? '—' : txn.note!),
),
// :241-247  标题「备注」
ListTile(
  title: const Text('备注'),
  subtitle: Text((txn.note == null || txn.note!.isEmpty) ? '—' : txn.note!),
),
```

**证据**：

1. 两处都渲染 **`txn.note`**（不是两个字段）
2. `transactions` 表**已无 `merchant` 列**（B4 的 v8 迁移已删，已复核）
3. 商户内容在 B4 时已通过 `composeNote` **并入 `note`**

**成因**：B4 把商户并进备注后，**忘了删详情页的「商户」行**。它现在读的是 `note`，
所以用户看到的是「商户: 星巴克 · 午饭」+「备注: 星巴克 · 午饭」——**同样的字出现两遍**，
而且第一行的标签已经名不副实。

**处理**：**删除「商户」整块**（含 `Divider`）。

### D2 · 首页概览 与 日历 的流水列表

- 首页概览：`:355-433` 区间流水列表（今天/昨天分组）
- 日历：`:462-...` 按选中日过滤的流水列表

## 2. 🟡 分层重复（**保留**，但加守卫）

| # | 信息 | 出现位置 | 为什么保留 |
|---|---|---|---|
| D3 | **净资产 / 总资产 / 总负债** | 首页概览卡 `home_page.dart:630` 附近；资产页 `assets_page.dart:235` | 首页是「一屏总览」，资产页是「管理页也要看净值」——少了任何一处都难用 |
| D4 | **区间收入 / 支出合计** | 首页卡（`$rangeLabel收入`/`支出`）；统计页（`支出合计` `:223` / `收入合计` `:257`） | 总览看总额，统计页看分类/每日明细 |
| D5 | **每日数据** | 日历「每日趋势」（**净额**，收入−支出）；统计「每日收入 / 每日支出」（可切换单侧） | 视角不同：一个看"当天净了多少"，一个看"收入构成" |
| D6 | **预算进度** | 统计页 `$label 预算`（`:536`）；预算页 | 统计页是进度摘要，预算页是配置 |

### 但 D3/D4 有**真实风险**：两处数字可能不一致

两页各自用**不同的 provider** 计算同一个数：

- 首页：`_netWorthHomeProvider`
- 资产页：`_netWorthBaseProvider`（`assets_page.dart:46-56`）

**建议**：加一个测试断言「同一账本、同一时刻，两处净资产相等」。
否则一旦哪天某个 provider 改了汇率口径，用户会看到两个不同的净资产——**比重复更糟**。

## 6. 给执行者的话

这次只发现 **1 个真 bug**（详情页商户行），其余都是设计层面的分层——
说明前几轮的结构其实没有想象中乱。

但那个 bug 值得记一笔：**它和商户合并是同一次改动留下的**。
B4 时把 `merchant` 并进 `note`，改了数据库、改了面板、改了迁移，**唯独漏了详情页那一行**。

**教训**：删字段时，除了写入口和迁移，还要**反查所有"读取该字段用于展示"的地方**——
这次漏掉的那处，恰好也在读 `note`，所以连编译都不会报错（`note` 还在），
**只有真的打开一笔账单详情才能发现**。

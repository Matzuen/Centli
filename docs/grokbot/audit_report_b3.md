### 🟠 P1：「订阅」与「周期记账」是同一件事的两套模型 —— 纯度问题

**这是本批最该被质疑的产品决策，而它是我开的单。**

| | 周期记账 | 订阅 |
|---|---|---|
| 管什么 | 定期自动**写流水** | 记录订阅、**到期提醒**、算花费合计 |
| 是否会入账 | 会 | **不会**（有测试证明） |
| 数据来源 | `transactions` | 独立 `subscriptions` 表 |
| 花费数字 | 统计页的支出合计 | 订阅页自己算的 `spend` |

**问题**：同一个"宽带每年 1200"，用户在两处各建一条，会得到**两个互不相干的数字**：

- 订阅页：「花费合计 ¥1200」
- 统计页：支出合计 ¥1200（来自周期记账）

表面上没重复计账（订阅不写流水），但**用户会看到两套"我的订阅花了多少钱"**。
这正是我在 B1/B2 反复批评的那类缺陷——**两个口径**（`include_in_stat` vs `include_in_budget`）。
现在我在订阅/周期这里**又造了一对**。

**以"纯粹单一"为标准，结论明确**：
「订阅管理」是**另一个产品**（订阅追踪器），不是记账软件的核心职能。
它给 App 增加了：1 个数据表、1 个设置入口、1 个列表页、1 个表单页、
**5 档状态**（active/cancelled/trial/owned/free）+ **5 种周期**（含 lifetime）。

**建议**：
- **方案 A（推荐）**：删掉订阅模块。想提醒续费就用周期记账 + 备注，或干脆不做提醒。
- **方案 B**：保留但**砍到 2 档状态**（在订/已取消），并**从周期记账的数据算花费**，
  不再自己存 `price`——消除两套数字。

### 🟡 P2：golden 测试没有目视价值（无法用来"对照 Finch"）

Bot 生成了 `bookkeeping_panel.png` / `_dark.png`。我看了，有两个硬问题：

**① 无字体 → 全是黑方块**

测试环境不加载字体，`Text` 渲染成 tofu。golden 里所有文字都是方块，
**无法判断文案、字号观感、chip 内容是否正确**。

**② 容器错位 → 不是真实形态**

```dart
home: const Scaffold(body: BookkeepingSheet()),   // ← 顶对齐，无圆角，无贴底
```

真实形态是 `showModalBottomSheet`（`isScrollControlled`、`useSafeArea`、
`safeArea`、顶部圆角 24、贴底）。golden 渲染的是"顶对齐的一块内容 + 下半屏空白"，
**连贴底都没体现**，更看不出顶部圆角。

**结论**：这个 golden 只能抓"几何数值漂移"，**抓不到它本该抓的东西**——
而用户要的恰恰是"看起来像 Finch"。

**我为了判断真伪，自己另做了一次渲染**（装载微软雅黑/黑体 + 复刻真实 modal 容器），
结果见 `_re_finch/ui_ref/panel_real_light.png`。
**结论：版式确实接近 Finch**（贴底圆角、右对齐金额、2 行 chip、5×4 计算器键盘、
配色、间距都对）。所以**产品本身没跑偏，是 golden 这个验收工具不合格**。

**建议**：golden 必须（a）加载一款固定字体，（b）在真实 modal 容器里渲染。
否则它给出的"通过"是虚假的安全感。

## 4. 对"纯粹、单一、好用"的整体判断

### 现在的 App 是不是一款纯粹的记账软件？

**核心是，但边缘在扩散。**

`我的`页现在有 **17 个入口**：

```
主题 · 账本管理 · 分类管理 · 预算 · 周期记账 · 订阅 · 自动记账 · 智能填单
桌面小组件 · 安全 · 汇率 · 回收站 · 已忽略通知 · 导出 · 导入 · 关于 · (debug)重新查看引导
```

**其中真正属于"记账软件"的**：账本、分类、预算、周期记账、导出入、回收站、汇率、安全
**属于"平台能力"的**：自动记账（核心差异化）、桌面小组件
**属于"别的产品"的**：**订阅**、智能填单（AI）、（未做的）心愿、借贷

**判断**：App 还在"纯粹的记账软件"范围内，但**已经站在边界上**。
再加 2–3 个"专项账务"模块，它就会变成 Finch 那样的全能财务 App——
而那**恰恰不是用户要的**。

### "好用"这一项，本批有一处退步

| 维度 | 变化 |
|---|---|
| 记账面板观感 | ⬆️ 明显像 Finch 了（版式实测接近） |
| 键盘 | ⬆️ 计算器式 4×5，有 `/ * =`，比原来的 5 列 + `00` 更符合直觉 |
| 分类/账户选择 | ⬇️ 从**带标签的下拉**变成**无标签的 chip** |
| 商户录入 | ⬇️ **消失** |
| 概念清晰度 | ⬇️ 周期记账 vs 订阅，两个入口讲同一件事 |

**关于 chip 的一个具体可用性隐患**（我在渲染图里确认）：
占位态和已选态**视觉一样**。截图里 `[标签][成员]` 是占位符、`[餐饮][现金]` 是已选值，
但看起来完全同类。用户扫一眼分不清"哪些还没填"——而旧版下拉有明确标签。
这在"好用"上是**真的退了一步**，不能因为"Finch 也这样"就当作没问题。

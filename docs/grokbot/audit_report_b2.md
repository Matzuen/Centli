## 1. 我核实到的真实缺陷（T1 收入漏抓）

### 1.1 `wechat_receive_zh` 模板自相矛盾（**必须修**）

`lib/platform/notifications/notification_parse.dart` 同一模板内：

```
第 250 行 mustContainRegex: '...|红包到账|你领取了.+红包|收到红包'
第 252 行 excludeTextRegex: '...|发来一个红包|领取了你的红包|退款'
```

而 `parseNotification` 的判定顺序是**先 exclude、后 mustContain**（`:318-325`）：

```dart
if (t.excludeTextRegex != null && RegExp(...).hasMatch(body)) continue;   // 先挡掉
if (t.mustContainRegex != null && !RegExp(...).hasMatch(body)) continue;  // 再要求
```

→ `领取了你的红包` 同时在"要抓"和"要挡"两边，**exclude 先执行所以必定被挡**。

### 1.2 实测：7 种真实措辞中 2 种漏抓

| 通知措辞 | 结果 | 判定 |
|---|---|---|
| `你领取了张三的红包` | ✅ `in` | 正确 |
| `你领取了一个红包` | ✅ `in` | 正确 |
| **`你领取了你的红包`** | ❌ **未捕获** | 🔴 **缺陷：模板自相矛盾** |
| **`你收到一个红包`** | ❌ **未捕获** | 🟠 **缺陷：正写过严** |
| `红包到账` | ✅ `in` | 正确 |
| `发来一个红包` | ❌ 未捕获 | ⚪ 设计取舍（对方发来，方向不确定） |
| `收款到账` | ✅ `in` | 正确 |

**第 4 行原因**：mustContain 写的是 `收到红包`（要求相邻），
而真实文案是 `收到一个红包`（中间有"一个"）→ 不匹配。

**手动/OCR 路径同一问题**：`:678` 的 exclude 也含 `领取了你的红包`，
所以截图/分享导入的红包收入同样抓不到。

### 1.3 修复建议（很小）

1. 从 `wechat_receive_zh` 的 `excludeTextRegex`（`:252`）**移除** `领取了你的红包`
2. 从手动路径 exclude（`:678`）**移除** `领取了你的红包`
3. mustContain 的 `收到红包` 改为 `收到.*红包`（容忍"一个/了"等插入词）
4. 建议补测试：把上面 7 种措辞固化进 `notification_parse_test.dart`

> **判断依据**：用户明确要求"**必须要收入/支出同时都能监听**"。
> 红包是微信最常见的收入场景之一，漏掉它等于该要求未完全达成。

## 2. 用户会卡住的地方

### 🔴 U1 · 记账面板没有"怎么关"的提示

**现象**：手动记账面板打开后——

```
（上方 30% 是变暗的背景）
┌──────────────────────────┐
│  支出   收入   转账        │  ← 第一行就是类型切换
│      ¥0.00 CNY           │
│  [时间][餐饮][现金][标签]  │
│  [ 备注 ]                 │
│  [  键盘 5×4  ]           │
└──────────────────────────┘
```

- **没有拖拽把手**（对比：其他 6 个底部弹层都设了 `showDragHandle: true`）
- **没有关闭/取消按钮**（`bookkeeping_sheet.dart` 里 `Navigator.pop` 只出现在子对话框里）

`showBookkeepingSheet` 的弹层参数：

```dart
return showModalBottomSheet<bool>(
  context: context,
  isScrollControlled: true,
  useSafeArea: true,
  // ← 没有 showDragHandle
  backgroundColor: ...,
  shape: ...,        // 只有顶部圆角 24
);
```

**用户实际退出方式**：点上方暗区，或按系统返回键。
**问题是没有任何视觉暗示**——而这是**打开频率最高的界面**，也是唯一没有把手的。

**我的判断**：这是 B1 定"不要关闭 X"时留下的副作用。
去掉 X 是对的（少一个视觉噪音），但**应当补一个拖拽把手**——它同时承担"这是可下拉关闭的面板"的暗示，且与其它弹层一致。

### 🟠 U2 · 退格键是"文字"，不是图标

```dart
1251:  ['AC', '\u232b', '/', '*'],      // U+232B = ⌫
```

**它不是 `Icon`，是一个文字字符。** 后果：

- 外观**取决于设备字体**（Android 靠系统回退字体才显示成 ⌫）
- 在 golden 渲染里直接变成**豆腐块**：

![退格键在 golden 里是缺失字形](_re_finch/shots/crop_backspace.png)

**但真机是正常的**（你之前的截图里能看到 ⌫）——所以这**不是坏掉的界面**，而是：

1. **设备相关性风险**：精简字体的 ROM 上可能显示为方框
2. **golden 永远不会发现它**——G4 加的图标字体只覆盖 `Icon`，覆盖不到文本字符
3. 与产品其他部分不一致：全 App 的图标都是 MaterialIcons，唯独这里用一个字符

### 🟠 U3 · 退格键和「清空」用了同一个"危险色"

```dart
1262:  if (k == 'AC' || k == '\u232b') return CentliTheme.keypadAcBg(context);
```

`AC`（清空全部）与 `⌫`（退一位）**共用同一个背景色**（golden 里两者都是粉色块）。

- `AC` 是"一键毁掉已输入内容"，用警示色合理
- `⌫` 是**高频操作**（输错一位就按），每次都看到警示色 → 长期视觉噪音，且暗示"这也危险"

**建议**：`⌫` 用普通按键色，只有 `AC` 保留警示色。

### 🟠 U4 · 首屏第一句话指向一个不存在的按钮

首页空态：

```dart
home_page.dart:420  '点底部「记账」记下第一笔'
```

但底栏那个按钮叫 **`记一笔`**：

```dart
shell.dart:19  label: '记一笔'
```

**「记账」≠「记一笔」**。新用户第一次打开就是空态，看到的第一句指引指向一个界面上没有的名字。

（`shell.dart:37` 的注释里也把它叫「记账」，同一处漂移。）

### 🟡 U5 · 「不计入统计」的流水在列表里看不出来

- 详情页有「计入统计」开关，关掉后该笔不进合计
- **列表行没有任何标记**（`includeInStat` 只出现在查询和详情页）

用户能碰到的两种情形：

| 情形 | 列表里能看到什么 | 会不会误解 |
|---|---|---|
| 余额校正 | 副标题显示「余额校正」 | 大致能认 ✅ |
| 还款（若自动置 0） | 显示备注文字 | 需要知道语义 |
| **手动关掉统计的普通支出** | **和普通支出一模一样** | ⚠️ 会觉得"合计漏了一笔" |

**这是最伤信任的一类问题**：数字加起来不对，但界面看起来毫无异常。

**建议**：列表行给一个极轻的标记（例如金额后一个灰色 `·` 或小标 `不计`），或至少长按/详情里能一眼确认。

## 3. 这次测试最重要的一条：golden 通过了坏界面

`bookkeeping_panel.png` 是**当前**的手机尺寸渲染（15:06 更新，含 G13/G14/G18 改动），
我把它放大看细节时，才发现退格键是个**豆腐块**。

也就是说：

> **我们的 golden 测试"通过"了一个图标没渲染出来的界面。**

原因很清楚：

- golden 锁的是**像素一致性**——只要每次都一样（包括一样的豆腐块），它就永远绿
- G4 加载 MaterialIcons，只解决 `Icon` 的字体问题
- **文本字符（`\u232b`）不在覆盖范围内**，而 golden 不判断"字形是否正确"

**这不是 golden 的错**，但说明一件事：**"测试全绿"不能替代"有人真的看一眼"。**
这也是这次为什么要换视角：325 个断言（225 测试）都没发现退格键少一条腿。

## 5. 我没能覆盖的（诚实边界）

- **手感**：滑动、点击反馈、动画节奏、键盘弹起时面板是否被顶起（真机才有）
- **通知自动记账的真机链路**（需要 Android + 通知权限）
- **语音按住说话的真机体验**
- **小屏（320dp）与超大字号下的排版**
- 深色模式下的其它页面（只看了记账面板）

这些**只能你在手机上用**才能发现——而这次发现的问题里，U1/U3/U4 你在日常使用中应该早已隐约感觉到（"这个面板怎么关"、"退格键怎么是红的"），只是没被写下来。
